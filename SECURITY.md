# Security and private reports

## Supported versions

Security fixes target the latest published release and the current default branch.
Older preview builds are not maintained separately. SkyBrowser currently has an
early 0.x API and application release series.

## Report privately

Use [GitHub private vulnerability reporting](https://github.com/Chuuei/SkyBrowser/security/advisories/new)
for suspected vulnerabilities. Include the affected version, reproduction steps,
expected impact and a minimal sanitized input when possible. Do not publish an
exploit or a private image in a public issue before discussing disclosure.
The same private route can be used for sensitive conduct concerns.

FITS/XISF headers, sessions, screenshots, logs and paths can reveal names, account
directories, acquisition times and observing locations. Remove personal data
before sharing them. Prefer a generated tiny fixture or anonymized metadata.
Never attach credentials, tokens, private keys, personal settings or a preview DB.

Report ordinary bugs through the bug-report form. Dependency alerts are reviewed
with the affected package's advisory; the absence of an alert is not a guarantee
that an arbitrary scientific file is safe.
